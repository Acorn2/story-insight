# 阅读体验与结构修改

用于起草后的阅读检查，以及用户反馈“不好读、没故事、开头留不住人”时的改稿。它与事实、归属及权益检查并行，不能互相代替。只有审查授权时报告问题，不擅自改写。

## 先确定在替谁读

沿用用户指定的目标读者。没有资料时，说明假设的读者所处情境、已有知识和阅读目的，例如“想在下班后找点乐子，但对自己的爱好总嫌不够好的普通读者”。不要凭空赋予其年龄、诊断或职业。

在当前会话中顺读成稿，暂时放下作者提纲，不靠提纲解释正文没写清的东西。记录的是对某类读者体验的推测，不是独立读者反馈、平台数据或心理测量；不需要额外 Agent、模型服务或分数。

先辨认这篇打算给读者什么：想看事情如何办成、享受相处的乐趣，还是感到紧张、刺痛或被理解。沿用文本与任务已有的取向，不要求每篇同时有笑点、悬念与启迪。事实解答另检查有没有说清问题与依据，不把小说的要求套给所有文章。

指定素材的故事读完后，复用本次分析中的保留与重建判断，已有获准记录时可参考，不为此新建文件，检查人物在乎的东西、困难和关键选择是否仍对应所选核心。好读的另一篇故事也可能没有完成取材任务；不要求通过复刻原案来证明关联。

## 将阅读信号变成编辑决定

先顺读，再把困惑、走神或牵挂定位到段落、短引语或场景。区分读到了什么、推测为什么如此、准备怎样处理；“读到这里走神”不能直接推出句子太长，“结局能猜到”也不能直接推出需要反转。

| 发现 | 怎样判断 | 编辑决定 |
|---|---|---|
| 因果、时间、视角或行动含义有缺口 | 指出哪处信息矛盾、缺失或指向不清，影响读者理解哪次行动；先确认不是有意保留、且不妨碍当前事件的未知 | 在授权内修正该缺口；不能编造真人细节 |
| 关键场景没有兑现，篇幅停在重复中 | 指出正文建立了哪种阅读期待，哪次应对被略过，或哪些段落没有增加信息、关系、感受；有效的日常与反复可保留 | 调整相关场景及详略，不自动扩写全文 |
| 另一种节奏、视角、人物解释或结尾可能更合口味 | 能否指出当前写法损害本篇理解或阅读期待？若只有偏好，注明理由和不确定性 | 留作审美备选，不自动执行 |
| 没发现有依据的缺陷 | 不为填满维度或证明自审有用而找问题 | 保留现稿，继续适用的文风及内容检查 |

“不够深刻”“人物不够复杂”“不够意外”本身不能启动改写。可以提出主观阅读感受，但须说明正文依据和影响，不能靠换成“资深作家”角色或一个分数让推测变成结论。不设评分环节或达标分数；用户明确要求评分时说明其主观尺度，不用评分代替具体判断。

## 只回查与信号有关的地方

以下用于找原因，不是每篇逐项完成的修改清单：

| 信号 | 回查方向 |
|---|---|
| 开头后不再关心接下来发生什么 | 本篇靠谜面、人物应对还是相处趣味吸引人？是否仅重复已知结论，或为悬念故意漏掉基本因果？可预料的走向、简单情节不自动构成缺陷 |
| 关键决定读不明白 | 谁要得到什么、对方在应对什么，具体接受或放弃了哪件事，前后有什么改变？按 [story-craft.md](story-craft.md) 回看必要前提；不要求解释全部动机或交代余生 |
| 场景像交代流程或轮流讲道理 | 是否反复向不同听众转述同一内容，最影响关系的回应却被概述？人物是否只为结论改变意愿？把篇幅留给有分量的实际应对 |
| 情绪、幽默或结尾失效 | 反应是否属于此人，类比是否解释当前关系，必要心理是否被删，后续是否只重复确认同一感受？不要求添缺点、强制和解、回收物件或删除一切尾声 |
| 好读却偏离指定素材 | 新起因是否替换了所选困境、成功是否回答了另一个问题？回查保留与重建说明，不靠复演原经历证明关联；只借主题时沿用用户范围 |

完整性、持续吸引力、人物可信度和声音可以有不同结论。安静、善意、开放结尾和没有成长都可以成立；有现实意义也不能抵消具体阅读阻力。事实解答看回答与证据，不套小说要求。

## 修改、交接与停止

只审查时给依据、成立的部分及处理优先级，不生成替代稿。允许改稿时，在现有记录简记“位置 → 阅读信号 → 判断依据 → 实际处理”，保留有效场景、情绪和授权范围；备选意见标清未执行，不新增评分表或专门报告。结构问题修事件与顺序，表达问题交给 [natural-voice.md](natural-voice.md)，事实与用途问题交给 [review-checklist.md](review-checklist.md)。

真人材料不能为连贯补写，独立虚构的修改须保持时间、视角、因果及取材要求。没有真实用户反馈时明确待用户审阅，不将模拟体验写成留存提升或用户满意。

修改后顺读受影响场景与连接处，确认原问题得到处理、必要因果与有效情绪仍在，再交接需保护的内容与未决项。已有结论复用；新缺陷返回对应阶段，不固定再跑一轮全文。没有待处理的具体缺陷即可交付，审美疑问留给用户，不以字数减少、对白增长、自评分提高或“还可以润色”证明修改必要。
