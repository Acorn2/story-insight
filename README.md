# Story Insight

从真实连麦、访谈和对话稿中理解困境及互动变化，写成独立虚构故事或有故事推进和独立判断的知乎、微信公众号文章草稿。故事围绕人物的愿望、阻力、选择与后果展开；现实论证按需核查资料。

故事分别检查完整性、开头与持续吸引力、人物反应和阅读回报。趣味可以来自好奇、幽默或关系变化，触动也可以来自牵挂与难堪，不强求启迪或成长。起稿时选择值得展开的应对，审稿时检查重复交代、关键场景略写和反复收束；不要求每个故事都提出主张、经历开导或回收开头物件。

默认将原对话用于内部发现议题，完整分析诉求、回应、补充及仍未解决的问题。指定稿件生成故事时，保留选定且有依据的关系或选择困境，在创作记录说明新人物和事件怎样承载它；仅借主题自由发挥由用户明确选择。对外稿件不披露主播、节目或连麦来源，不复述可识别的人物网络及具体经历链；故事由独立材料或明确标示的独立虚构承载。改名、删除出处或拼接多人经历不能代替这一步。内部创作记录不随正文对外分发，独立公开资料仍按需引用。

Skill 位于 [`.agents/skills/story-insight/SKILL.md`](.agents/skills/story-insight/SKILL.md)，可连同其 `references/`、`agents/` 整个目录复制使用。没有 Python/Node 运行依赖、CLI、数据库或网页；本次未安装到全局目录。

## 使用

如果当前会话已经发现该 Skill，使用 `$story-insight`；未发现时直接要求读取入口：

```text
读取当前项目 .agents/skills/story-insight/SKILL.md，按这个 Skill 执行。
分析 /绝对路径/对话稿 目录中的全部稿件，给出值得写的选题、依据和不建议使用的部分。
本轮只选题，不写文章。
```

完整创作：

```text
使用 $story-insight，围绕我指定的对话稿做全流程。
自主提炼一个适合独立研究的问题，用独立资料或明确的假设组织叙事，完成资料核验、知乎和公众号草稿。
不披露原连麦来源，不复述原人物经历或特殊情节组合。
从目标读者视角检查开场、中段和结尾，再检查模板腔、人物声音及事实边界；不套先给结论再列道理的固定写法。
结果保存到当前工作区的 outputs/，不发布。
```

指定问题与平台：

```text
读取当前项目 .agents/skills/story-insight/SKILL.md。
围绕“业余爱好一定要追求进步吗”写一篇知乎草稿。
不使用真实人物细节；查证必要资料，给出来源和配图建议。
```

参考对话另写故事：

```text
使用 $story-insight，完整阅读我指定的对话稿，包括诉求、回应以及补充后问题怎样变化。
选定一条有原文依据的关系或选择困境，在内部记录说明保留什么、新人物和事件如何承载它。
另写一篇适合知乎阅读的独立虚构故事，明确标示，不披露来源或回放可识别的原案经历。
检查新增起因是否改了主线，写出关键对话、选择和代价；不要用一次成功替所有人决定，也不要在结尾附一串道理。
完成取材关联、阅读体验、去模板腔和事实边界检查，新版本另存，不发布。
```

执行时分别确定任务范围与作品体裁：全流程决定完成哪些阶段，不自动决定采用虚构。仅选题到选题停止；只审查不改正文；局部文风修改直接读取所需上下文与编辑规范，无须重新选题。已明确全流程时连续完成，不强制逐阶段确认。

故事起稿先理清人物当下想得到什么、对方怎样应对及关键行动改变什么；不清楚时先试关键场景，已有写法就直接起稿。自审区分可定位缺陷与审美备选，不固定打分或要求每篇再改一遍；没有有依据的问题可以保留初稿。明确要求评分时提供主观判断，不以分数决定是否重写。

重写无聊草稿时可以直接要求：

```text
使用 $story-insight 重写我指定的稿件。
保留有依据的事实与核心判断，先找具体困境和关键变化，再重组开场、信息顺序与结尾。
不要只换词加梗；完成读者顺读、去模板腔编辑与事实检查，新版本另存。
```

已有故事读起来像模板时：

```text
使用 $story-insight 修改我指定的现有故事与创作记录。
先定位故事、用笔和声音中的具体问题，再在保留事件、动机、选择及结局的范围内去模板腔。
不强行加意外、粗话、口头禅或无关小动作；必要的心理直写和自然停顿保留。
先保住已有声音与情绪，再调整中文语序、前后照应和段落节奏，不把正文剪成对白提纲。
另存新版本，在创作记录保留少量改前后对照，不以自评分或检测器分数宣称效果。
```

## 输出

- 选题任务：一份 `选题.md`，包含阅读覆盖、候选题、取舍和限制。
- 完整写作：所需平台正文及一份 `创作记录.md`，合并叙事路线、证据、阅读体验发现、结构与文风的实际改动、必要对照、疑点及配图策划。
- 未指定输出位置时使用 `outputs/日期/议题/v01/`，新版本不覆盖旧文件。该目录不纳入 Git。

配图仅提供位置与提示词，不包含实际生图。所有文章均为草稿，不自动操作发布平台，不将主播建议自动认定为事实、专业意见或用户观点。

范围见 [MVP.md](MVP.md)，执行方式见 [ARCHITECTURE.md](ARCHITECTURE.md)，技术取舍见 [TECH-STACK.md](TECH-STACK.md)。实际验收及未覆盖项记录在 [validation/acceptance.md](validation/acceptance.md)。

## 示例与维护

- [知乎议题文章](examples/hobby/v02/知乎.md)、[公众号议题文章](examples/hobby/v02/公众号.md)及[创作记录](examples/hobby/v02/创作记录.md)：展示假设情景怎样辅助判断，不作为完整独立故事示范。[旧稿](examples/hobby/知乎.md)保留作对照。
- [独立虚构故事《往左一点》](examples/group-photo/v01/故事.md)及[回读记录](examples/group-photo/v01/创作记录.md)：展示无源稿的轻松生活故事与人物应对，来源和检查范围在记录中说明。
- [局部编辑对照](examples/local-edit/对照.md)：展示自然表达、信息保真与授权范围控制，数字及情境明确为合成测试材料。
- 独立故事设计支持在方向未定时比较视角与关键场景，先试写最能检验方案的一场戏；已有明确路线或局部改稿跳过此步。
- 指定素材的关联尺度对照位于 [分析规范](.agents/skills/story-insight/references/analysis-and-topic.md#用对照校准关联尺度)，区分取材关联不足与具体事件重建不足。
- 结构编辑向文风编辑交接主要问题、需保护内容与未决项；事实审校只核对适用边界，不重新启动整轮润色。

方法出处及固定版本集中在 [method-sources.md](.agents/skills/story-insight/references/method-sources.md)，仅维护时读取，不依赖外部 Skill 安装。开发用的固定合成输入、同题请求及对照方法见 [comparison-cases.md](validation/comparison-cases.md)，不是日常写作的必跑流程。

历史验收及各次局限见 [validation/acceptance.md](validation/acceptance.md)。样例的实际读者反馈与未验证事项分别保留在对应记录中，自审和元数据检查不代表文学质量通过。
