# Story Insight

提供原始文稿，先判断是否有写作价值与传播潜力；适合时得到一份新的结果文稿，不适合则说明原因后结束。需要图片时，再单独为成稿配图。目标平台可指定微信公众号、今日头条、百家号、知乎等，不限于知乎。

仓库有两个独立 Skill：[story-insight](.agents/skills/story-insight/SKILL.md) 负责写作，[story-visualizer](.agents/skills/story-visualizer/SKILL.md) 负责配图。各自目录可独立复制；写作不需要安装运行依赖，实际生图使用当前环境已有的图像工具。

原对话用于内部理解困境和互动，文章独立组织；事实、观点、假设和虚构分别处理。不披露主播或连麦来源，不回放可识别的原人物经历；独立虚构须明确标示，不能冒充真人经历或现实证据。

## 最终文件长什么样

```text
outputs/文章简称/
  结果文稿.md
  图片/                      # 后续要求配图时才增加
    01-封面兼配图.png
    02-配图.png
    03-配图.png
  配图说明.md                 # 每张图的用途和正文插入位置
```

预检查通过并写作时只有 `结果文稿.md`；未通过的写作任务只在回复中给结论和具体原因，不创建文章目录或报告。默认不套日期、平台、版本目录，不额外交创作记录、manifest、prompt、视觉设定、发布包或带图副本。分析、必要核验和审校仍完成，影响使用的局限在回复中简述。

## 第一步：处理文稿

提供原稿路径、写作要求及目标平台，单独发出写作指令：

```text
使用 $story-insight，读取 /绝对路径/原始文稿.md。
先完整阅读并预检查写作价值与传播潜力，没有合适角度就说明原因后结束，不硬写。
通过后按我的要求处理成一篇适合微信公众号阅读的文章，区分事实、观点及假设，不补写真人经历。
写作时完成必要审校，只保存到 outputs/文章简称/结果文稿.md。
本轮只写作，不生成图片或过程文档，交付后停止。
```

预检查关注陌生读者为什么在意、为什么愿意点开、正文靠什么持续展开，以及能否独立写成；这些是编辑判断，不保证流量或收益。完整读完没有合适角度时返回“不适合本次写作”；未读全或关键材料缺失时返回“暂时无法判断，暂停写作”，说明最小补充需求。通过后已有写作授权就直接继续，不再等一次确认。只想先判断时可明确要求“本轮仅预检查，不写正文”，默认只在回复中给结论。

写作默认一篇、一份结果文件；只有明确要求时才输出多个平台版本或创作记录。原始输入保留不动。同一任务改稿在原目录另存 `结果文稿-2.md`，不再套一层版本目录。只选题或只审查也只交对应结果，不生成文章或配图文件。

无源稿时可直接给题目；需要独立虚构故事时明确体裁及虚构标记。无源稿命题创作、现稿审查和局部编辑不强套原稿预检查。仅要求表达自然，不等于允许虚构。写作全流程包括适用审校，文章交付后停止，不自动生图。

## 第二步：单独配图

取得文章后，另发指令指定结果文稿的准确路径：

```text
使用 $story-visualizer，为 outputs/文章简称/结果文稿.md 配三张图。
其中一张兼作封面，不额外生成封面。
图片放在这篇文章旁边的“图片”子目录。
再写一份“配图说明.md”，说明哪张是封面、每张图在正文哪一段后面。
不改正文，不生成其他过程文件或图文副本，不发布。
```

默认通常两到三张，**每篇正文最多四张，其中一张兼作封面**；已有、复用和新增图片合并计数。文件名用“封面兼配图”标明封面，普通图用“配图”。封面复用同一张图片，不多生成一张。

`配图说明.md` 写明对应稿件和封面文件，并用一张表说明位置：

| 图片 | 用途 | 插入位置 | 状态 |
|---|---|---|---|
| 图片/01-封面兼配图.png | 封面兼正文图 | 某小节，原文完整段落“……”之后 | 已生成，已检查 |
| 图片/02-配图.png | 正文图 | 原文另一完整段落“……”之后 | 已生成，已检查 |

实际交付必须把“……”换成原文中能唯一定位的段落，不能只写“开头”“中间”。不要求你读 JSON 或逐图 prompt 才知道怎么用。

只想先看方案时，要求“只做配图策划，不生图”，只交这一份说明并标记“图片未生成”；不会创建空图片目录。无生图工具时也如实交代，不生成假图片。只要封面则只生成一张，并在位置列注明“仅封面，不插正文”。

后续可说“补说明中失败的图”或“只重画第二张”。成功图不动，重画用如 `02-配图-2.png` 和 `配图说明-2.md` 保留旧文件，不复制整套目录。默认不修改结果文稿；只有明确要求自动插图时才另存带图稿。

生图后实际打开检查图意、隐私、人物和画面可用性；失败项在同一说明标注，不自动反复重画。费用未知时明确说明。默认无字、16:9、克制电影感插画；图片不能保证跨图同脸，所有结果仍待用户审阅，不自动发布。

## 调用与边界

会话未发现 Skill 时，把示例第一行替换为“读取当前项目 `.agents/skills/story-insight/SKILL.md`”或“读取当前项目 `.agents/skills/story-visualizer/SKILL.md`，按该 Skill 执行”。

原始文稿只读，配图只读取指定对外结果稿，不默认读取原连麦、创作记录或真人照片。普通任务写入被忽略的 `outputs/`；开发试跑使用被忽略的 `.tmp/`，不再混入日常结果。历史复杂目录保留，不自动批量搬迁或删除。

范围见 [MVP.md](MVP.md)，工作方式见 [ARCHITECTURE.md](ARCHITECTURE.md)，技术选择见 [TECH-STACK.md](TECH-STACK.md)。历史验收与局限见 [写作验收](validation/acceptance.md)、[配图验收](validation/visual-acceptance.md)，历史输出结构不作为当前交付模板。

## 示例与维护

- [知乎议题文章](examples/hobby/v02/知乎.md)、[公众号议题文章](examples/hobby/v02/公众号.md)及[创作记录](examples/hobby/v02/创作记录.md)：展示假设情景怎样辅助判断，不作为完整独立故事示范。[旧稿](examples/hobby/知乎.md)保留作对照。
- [独立虚构故事《往左一点》](examples/group-photo/v01/故事.md)及[回读记录](examples/group-photo/v01/创作记录.md)：展示无源稿的轻松生活故事与人物应对，来源和检查范围在记录中说明。
- [局部编辑对照](examples/local-edit/对照.md)：展示自然表达、信息保真与授权范围控制，数字及情境明确为合成测试材料。
- 独立故事设计支持在方向未定时比较视角与关键场景，先试写最能检验方案的一场戏；已有明确路线或局部改稿跳过此步。
- 指定素材的关联尺度对照位于 [分析规范](.agents/skills/story-insight/references/analysis-and-topic.md#用对照校准关联尺度)，区分取材关联不足与具体事件重建不足。
- 结构编辑向文风编辑交接主要问题、需保护内容与未决项；事实审校只核对适用边界，不重新启动整轮润色。

方法出处及固定版本集中在 [method-sources.md](.agents/skills/story-insight/references/method-sources.md)，仅维护时读取，不依赖外部 Skill 安装。开发用的固定合成输入、同题请求及对照方法见 [comparison-cases.md](validation/comparison-cases.md)，不是日常写作的必跑流程。

历史验收及各次局限见 [validation/acceptance.md](validation/acceptance.md)。样例的实际读者反馈与未验证事项分别保留在对应记录中，自审和元数据检查不代表文学质量通过。
