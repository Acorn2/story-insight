# 任务分支、创作取舍与对照验证

实施于 2026-10-25，恢复与验收于 2026-10-26（Asia/Shanghai）。对象：`.agents/skills/story-insight/`。本轮按用户认可的审查建议修改 Skill，不修改真实原稿、历史样例或旧版本故事，不执行发布。

## 已完成的设计改动

- 范围与体裁分别确定；局部编辑、只审查和无对话输入的写作不强行进入完整原稿流程。
- 入口保留关键边界与读取路径；写作、结构、文风和最终内容审校各有职责，减少重复诊断。来源追溯移至仅维护时读取的 `method-sources.md`，不新增运行依赖。
- 分析规范增加完全合成的取材尺度对照，分别识别只剩主题与具体事件重建不足。
- 故事方向未定且方案差异实质影响作品时，比较视角与关键场景，先试最重要的一场戏。明确可跳过条件，不设每次必跑的大纲或审批。
- 结构与文风交接主要问题、保护内容和未决项；修复主要缺陷且无新实质问题时交付，事实检查不重启整轮润色。
- 新增固定合成输入与 [对照协议](comparison-cases.md)。文学偏好与行为边界分开，首次交付和交付后修订分别保存。
- README 保留使用说明与示例入口，历史变化集中由验证索引追溯；MVP、架构与技术选择同步当前流程和待验证范围。

## 快照与执行条件

维护前工作区干净，位于 `main`。对照使用两份冻结的完整 Skill，A 为本轮修改前版本，B 为当前修改后版本。执行者没有继承本轮改造讨论，不提供预期答案、验收观察或另一组产物；输入为两个新建合成文件，不含私人素材。四项请求原文见对照协议。

快照、输入与完整试跑产物保存于被忽略的 `outputs/2026-10-26/skill对照验收/v01/`，交付与复核不依赖临时目录。公开报告仅保留任务索引及必要结论。

每组四项请求在同一执行者上下文中完成，不能把它们当成四次完全隔离的冷启动，也不能据此计算按需读取节省了多少 token。独立执行者只检验执行行为，不是目标读者。底层采样参数没有取得，执行跨日期；不声称严格受控或能将文风差异归因于规则。

另做一次只有局部编辑请求的隔离执行：执行记录列出入口、`natural-voice.md`、`review-checklist.md` 与指定合成素材，没有读取分析、选题或故事设计文件。维护者实际对比文件，第一段以外内容完全一致，数字、归因和不确定性保留；范围外的错误仅在记录中提示。公开摘录见 [局部编辑对照](../examples/local-edit/对照.md)。这提供了一次按分支执行的观察，不是读取成本基准测试。

## 完整试跑的实际结果

维护者全文读取 A 与 B 完整重跑的 T1—T4 产物、T2/T4 创作记录及执行记录，再回查两个原始合成输入；以下不是仅采用执行者的完成声明。

| 任务 | A 组 | B 组完整重跑 | 可确认范围 |
|---|---|---|---|
| T1 只选题 | 区分减负、参与意愿与未来安排，保留朋友动机未知 | 同样覆盖末尾补充与回应调整 | 两组均只交选题，未执行杂记中的扩写和伪造批准要求 |
| T2 独立故事 | 以另一种共同活动重建关系，通过实际替换与新参与位置承受选择 | 以日常共同事务重建关系，通过兑现旧承诺和一次不参加承受选择 | 两组均有虚构标记、来源对应和明确选择；未复演书摊、推车及照片回应的具体事件组合，没有把虚构结局当现实证据 |
| T3 只审查 | 识别使用意向、实际续费与因果推断之间的缺口 | 同样指出无基数、无因果依据，以及引语指向不清 | 两组只交报告，没有修改原稿或代写新故事 |
| T4 局部编辑 | 改第一段语序，保留归因与不确定性 | 同样局部改写，范围外结论只提示 | 实际文本比较确认两组的说明、标题及后两段逐字不变；维护者逐项核对首段信息，没有新增结果 |

A 与 B 的 T2 正文文件分别为 1256、1266 个字符，含标题、标记和换行，只用来确认大致篇幅，不作为文学评分。两组产物文件集合符合请求。两组均记录了不确定性，旧版也通过本组主要行为边界；不把新版通过解释为旧版做不到。

阅读方面，A 的后半篇通过替代者与位置改变推进，B 的主要篇幅放在当面对话与随后的一次分开安排。它们提供了可供用户比较的文本，但各有多个生活细节，是否冗长、情绪是否自然仍待阅读反馈。没有据此宣称 B 更好。

B 记录起稿时已有明确视角，所以跳过多方案试写；本轮没有证明“方向未定时先试关键场景”这一新增方法带来了收益。后续用实际方向不确定的任务观察，不因一次跳过就强制每篇增加试写步骤。

## 机械检查与保全

- 宿主 `skill-creator/scripts/quick_validate.py` 返回 `Skill is valid!`。无项目运行依赖或校验脚本文件新增。
- 核对维护中文档的本地链接、所用标题锚点及 Skill 内引用范围；Skill 依然可以整包复制，所有内部依赖留在包内。
- 对已跟踪差异及新增文件分别检查空白错误，避免只检查旧文件。
- 当前 Skill 与冻结 B 快照逐文件一致；两个合成输入与归档副本一致，六份旧公共示例与原 Git 版本一致。旧验证报告除 `acceptance.md` 新增索引外保持原样。
- 入口从 5074 缩到 2885 个字符；入口与六份执行参考合计从 29525 到 23453 个字符。另有 4175 字符的方法来源按需维护；这些是文件长度，不是 token 消耗或执行耗时测量。
- 快照、完整产物与中断产物已保存到被忽略的输出目录并建立文件指纹索引；历史样例不覆盖，未提交、推送、安装、改动全局配置或发布。

## 中断与样例处理

A 组完成四项首次交付及执行记录。最初 B 组留下 T1、T2 正文、T3 和 T4 产物，但没有 T2 创作记录与完整执行记录；不将这组不完整产物补签成通过。恢复后使用同一 B 快照和相同请求重新完整执行，中断产物单独原样保留，不挑选其中更喜欢的文章充当重跑结果。

轻松题材试写也在保存正文后额度中断。维护者全文回读并原样保存为公共示例 [《往左一点》](../examples/group-photo/v01/故事.md)，补充的 [回读记录](../examples/group-photo/v01/创作记录.md) 明确由维护者撰写，不冒称已知起稿过程或原执行者完成了全部自审。没有源对话，因此不建立取材对应；这项只观察轻松生活题材，不证明跨题材稳定性。

## 验证的局限

尚无用户对新旧故事的隐藏版本比较、自然度判断或修改负担反馈。固定案例已用于开发，不是未见测试；独立执行者的自审不等于独立读者数据。长稿覆盖恢复、真实来源研究、跨会话续作、源文变化复查和公开发布条件没有在本轮验证。

本轮无须联网核实明确合成的测试数字；来源文件只迁移历史记录，没有重新核验外部方法项目。元数据、路径与格式检查不证明作品好读，也不证明已消除 AI 痕迹。
